# PROV-O — Provenance Ontology

**Authority:** W3C PROV-O Recommendation (2013); PROV-DM data model
**Witness key:** `prov-o` — `WitnessFamily::Standard`

---

## Overview

PROV-O is the W3C OWL ontology for representing provenance information — the who, what,
when, and how of information production. It enables any process artifact to carry a
traceable chain of custody from raw data to board-level projection.

---

## Core PROV-O Types

| PROV-O class | Definition |
|---|---|
| `prov:Entity` | A physical, digital, or conceptual thing with fixed aspects. An event log, a process model, a conformance result, a receipt. |
| `prov:Activity` | Something that occurs over a period of time and acts upon or with entities. Discovery, conformance checking, projection, graduation. |
| `prov:Agent` | Something that bears responsibility for activities and entities. A discovery algorithm, a user, a wasm4pm engine instance. |

| PROV-O property | Definition |
|---|---|
| `prov:wasGeneratedBy` | An entity was generated by an activity. |
| `prov:used` | An activity used an entity (consumed as input). |
| `prov:wasAttributedTo` | An entity was attributed to an agent. |
| `prov:wasDerivedFrom` | An entity was derived from another entity. |
| `prov:wasAssociatedWith` | An activity was associated with an agent. |
| `prov:startedAtTime` / `prov:endedAtTime` | Temporal bounds of an activity. |

## Provenance Chain: Raw Event to Board Projection

Every board-level claim in the process intelligence stack must be traceable to raw event
evidence. The PROV-O chain for a conformance result looks like:

```
RawOtelTrace         (prov:Entity)
    │ prov:wasGeneratedBy OtelIngestionActivity
    ▼
OcelLog              (prov:Entity)
    │ prov:wasDerivedFrom RawOtelTrace
    │ prov:wasGeneratedBy OcelAdmissionActivity
    ▼
AdmittedOcelLog      (prov:Entity — Admission<OcelLog, Ocel20>)
    │ prov:wasGeneratedBy DiscoveryActivity
    ▼
ProcessModel         (prov:Entity — e.g. Powl, WfNet)
    │ prov:wasGeneratedBy ConformanceActivity
    ▼
ConformanceResult    (prov:Entity — Metric<FITNESS, NUM, DEN>)
    │ prov:wasGeneratedBy ProjectionActivity
    ▼
BoardProjection      (prov:Entity — XES export with LossReport)
```

## wasm4pm-compat Implementation (receipt.rs, witness.rs)

### receipt.rs — The provenance bearer

`src/receipt.rs` defines the structural shapes that carry provenance:

- `ReceiptShape` — pairs a `Witness` key, a `Digest` (opaque hash string), and a
  `ReplayHint` (how to reproduce the computation). This is the `prov:Entity` wrapper for
  any process artifact.
- `ReceiptEnvelope` — wraps a `ReceiptShape` with a timestamp and an agent label,
  corresponding to `prov:wasGeneratedBy` + `prov:startedAtTime`.
- `ReceiptChain` — an ordered sequence of `ReceiptShape`s representing a full
  `prov:wasDerivedFrom` chain: raw → admitted → projected → graduated.
- `GraduationReceipt` — the terminal receipt when a shape graduates to `wasm4pm`;
  corresponds to the final `prov:wasGeneratedBy` edge in the provenance chain.

None of these compute digests or verify claims. They carry provenance shapes. Digest
computation and verification graduate to `wasm4pm`.

### witness.rs — The authority label

`Witness` markers are the `prov:Agent` labels in this stack. Each empty-enum witness:

- `KEY` — a stable machine-facing identifier (e.g. `"ocel-2.0"`, `"wf-net-soundness"`).
- `TITLE` — a human-facing authority name.
- `YEAR` — the year the standard or paper was published.
- `FAMILY` — the witness family (`Standard`, `Paper`, `ApiGrammar`, `RustLaw`,
  `InternalBridge`).

An `Admission<T, Ocel20>` carries the provenance claim "this value was admitted against
the OCEL 2.0 standard by the `Ocel20` authority." The witness is the `prov:Agent`
responsible for that admission.

### Loss accounting as provenance

`src/loss.rs` `LossReport<From, To, Items>` records:
- `From` — the source format (a `prov:Entity` type parameter).
- `To` — the target format.
- `Items` — what was discarded in the projection.

This is a structured `prov:wasDerivedFrom` with explicit loss accounting. The
`ProjectionName` is the `prov:Activity` name for the projection.

---

## Board Placement

Every board-level claim — fitness score, compliance rate, M&A due diligence finding —
must be backed by a `ReceiptChain` traceable through PROV-O to raw event evidence. The
`wasm4pm-compat` structures (`ReceiptShape`, `ReceiptChain`, `GraduationReceipt`, witness
markers) are the structural vocabulary of that chain. Without them, a board projection is
an assertion. With them, it is a provenance-backed claim.
