# process-intelligence v2030.1.1 — PRD / ARD

**Repository:** `seanchatmangpt/process-intelligence`  
**Ecosystem role:** research / process-intelligence authority  
**Release:** Chatman Ecosystem v2030.1.1  
**Standing conferred:** `UNKNOWN`.

## Product requirement

`process-intelligence` SHALL turn observed enterprise execution into a bounded, queryable, replayable process model. Its 2030 purpose is to provide the research and semantic basis for discovering how work actually flows across software, cloud, marketplaces, people, policies, and business objects so the ecosystem can optimize real processes rather than static diagrams.

The repository SHALL make **process reality an observation source**, not an actuation authority.

## Required capabilities

1. Represent event data with object-centric semantics, preferring OCEL-compatible structures when applicable.
2. Model processes, activities, objects, resources, timestamps/logical time, variants, conformance, waiting, rework, bottlenecks, handoffs, and deviations.
3. Maintain provenance from derived process models back to source observations.
4. Support deterministic extraction of bounded process graphs from admitted event corpora.
5. Provide research-grounded implementations or executable references for discovery, conformance, performance, and simulation methods.
6. Bind algorithm claims to papers/datasets/fixtures/metrics rather than prose-only assertions.
7. Distinguish `SIMULATED`, `OBSERVED`, `EXECUTED`, and `VERIFIED` results.
8. Export semantic findings that `wasm4pm`, `mfact`, `gymact`, `praxis`, and AutoFDE can consume without inheriting unsupported certainty.

## Architecture requirements

```text
raw events / traces / logs / enterprise objects
        -> observation normalization
        -> admission + provenance
        -> object-centric event graph
        -> discovery / conformance / simulation
        -> bounded findings
        -> receipts / downstream semantic projections
```

Research outputs SHALL be candidates until independently admitted. Model quality metrics, process discovery results, and simulation outcomes SHALL carry their corpus identity, algorithm identity, parameters, and uncertainty boundaries.

No process-mining algorithm may directly mutate production state. Optimization findings manufacture intents for downstream planning; DO remains outside this repository.

## DfCM contract

The repository SHALL preserve multiple plausible process explanations and intervention candidates when evidence does not justify a single irreversible interpretation. One failed conformance edge is topology evidence, not proof the whole process model is invalid.

## Acceptance for v2030.1.1

The repository reaches its v2030.1.1 target only when representative enterprise event corpora can be:

- admitted with explicit provenance;
- projected into object-centric process state deterministically;
- analyzed by at least discovery, conformance, and performance lanes;
- replayed against fixed corpus/algorithm identities;
- exported into machine-readable semantic findings;
- challenged by negative or counterexample fixtures;
- consumed by downstream process-execution and AutoFDE planning without converting research inference into actuation authority.

Benchmark receipts SHALL identify exact source, dataset, configuration, algorithm, metrics, and result. `ALIVE` requires observed execution against the exact admitted subject.

## Falsifiers

The architecture is falsified if a result cannot be traced to the events that produced it; if simulation is reported as observed process truth; if changing unordered input iteration changes a deterministic result; or if a research artifact can directly actuate an external system without a separate authority boundary.

## Ecosystem contract

This repository supplies **process knowledge**. `wasm4pm` owns process execution surfaces, `gymact` owns executable environment/action modeling, `mfact` owns formal certification where required, and BRCE-governed runtime components own consequential actuation.
