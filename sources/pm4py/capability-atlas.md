# PM4Py Capability Atlas (v30.1.1 Oracle Mapping)

## 1. Topographic Overview
PM4Py serves as the baseline comparative oracle. It maps process reality into static dataframes, projecting temporal event logs into memory-bound structures. This atlas categorizes its capabilities not for emulation, but for transcending its limitations through our AGI-adversarial lifecycle actuation.

## 2. Core Functional Domains
*   **Discovery:** Alpha, Inductive, Heuristics miners.
    *   *Oracle Constraint:* Assumes retrospective completeness. Operates on dead data (post-mortem).
    *   *Our Actuation:* Predictive, real-time discovery via continuous ontology synthesis.
*   **Conformance:** Token-based replay, alignments.
    *   *Oracle Constraint:* Rigid boundary mapping. Fails under AGI-driven non-linear process mutations.
*   **Enhancement:** Decision mining, bottleneck analysis.
    *   *Oracle Constraint:* Reactive overlay. Relies on statistical averages over dataframe snapshots.

## 3. Dimensionality & Constraints
PM4Py fundamentally operates in a 2D constraint space: `[Case ID, Timestamp]`. It struggles with multi-dimensional object-centric process models without forcing them into flattened relational schemas (OCEL notwithstanding).
