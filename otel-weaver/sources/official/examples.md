## 1. Complete Custom Registry Example

This registry describes an ordering and payment processing system.

### 1.1. `manifest.yaml`
```yaml
name: "ecom-telemetry-conventions"
description: "E-Commerce System Telemetry Semantic Conventions Contract"
schema_url: "https://opentelemetry.io/schemas/1.25.0"
dependencies:
  - name: "semconv"
    registry_path: "https://github.com/open-telemetry/semantic-conventions.git@v1.25.0[model]"
```

### 1.2. `groups/orders.yaml`
```yaml
file_format: "definition/2"
groups:
  - id: ecom.order
    type: attribute_group
    brief: "Attributes describing customer orders."
    prefix: ecom.order
    attributes:
      - id: id
        type: string
        brief: "The unique checkout transaction ID for an order."
        stability: stable
        requirement_level: required
        examples: ["order-9903-a", "order-1284-x"]
      - id: total_amount
        type: double
        brief: "The total cost of the order including tax and shipping."
        stability: stable
        requirement_level: required
        examples: [49.99, 1250.00]
      - id: currency
        type: string
        brief: "The 3-letter currency code (ISO 4217)."
        stability: stable
        requirement_level: recommended
        examples: ["USD", "EUR"]

  - id: ecom.order.processed
    type: event
    brief: "Event emitted when an order has been successfully paid and processed."
    attributes:
      - ref: ecom.order.id
        requirement_level: required
      - ref: ecom.order.total_amount
        requirement_level: required
      - ref: ecom.order.currency
        requirement_level: recommended
```

## 2. Complete Code Generation Template Example

This template generates a Go helper package representing the telemetry attributes.

### 2.1. `templates/go/weaver.yaml`
```yaml
whitespace_control:
  trim_blocks: true
  lstrip_blocks: true
  keep_trailing_newline: true

text_maps:
  go_types:
    string: "string"
    int: "int64"
    double: "float64"
    boolean: "bool"

acronyms:
  - "ID"
  - "ISO"
  - "USD"

comment_formats:
  go_doc:
    format: text
    prefix: "// "
    trim: true
    enforce_trailing_dots: true

params:
  package_name: "ecom_semconv"

templates:
  - template: "attributes.go.j2"
    filter: ".groups[] | select(.type == \"attribute_group\")"
    application_mode: each
    output_path: "attributes_{{ group.id | replace(\"ecom.\", \"\") }}.go"
```

### 2.2. `templates/go/attributes.go.j2`
```jinja2
// Code generated by OpenTelemetry Weaver. DO NOT EDIT.
// Upstream schema: {{ schema_url }}

package {{ params.package_name }}

{% if group.brief -%}
// {{ group.brief | comment("go_doc") }}
{%- endif %}
const (
	{%- for attr in group.attributes %}
	{%- if attr.brief %}
	// {{ attr.brief | comment("go_doc") }}
	{%- endif %}
	{{ group.id | replace(".", "_") | upper }}_{{ attr.id | replace(".", "_") | upper }} = "{{ group.prefix }}.{{ attr.id }}"
	{%- endfor %}
)
```

## 3. Complete Rego Policy Example

This policy enforces that all custom attributes in the registry start with the `ecom.` prefix, and all metrics have a brief description.

### `policies/naming_conventions.rego`
```rego
package weaver

# Critical check: Deny if an attribute does not use the org prefix
deny[msg] {
	attr := input.attributes[_]
	not startswith(attr.id, "ecom.")
	msg := sprintf("Policy Error: Attribute '%s' must begin with 'ecom.' prefix", [attr.id])
}

# Critical check: Deny if a metric is missing the metric_name field
deny[msg] {
	group := input.groups[_]
	group.type == "metric"
	not group.metric_name
	msg := sprintf("Policy Error: Metric group '%s' is missing required 'metric_name' property", [group.id])
}

# Warning check: Warn if an attribute is missing documentation
warn[msg] {
	attr := input.attributes[_]
	not attr.brief
	msg := sprintf("Policy Warning: Attribute '%s' is missing a 'brief' description", [attr.id])
}
```

## 4. CLI Execution Invocations and Expected Output

Here are CLI invocations and their expected console output.

### 4.1. Run Check (Successful validation)
```bash
weaver registry check \
  --registry ./my-registry \
  --policy ./policies
```
**Expected Output**:
```text
Checking registry 'ecom-telemetry-conventions' from path ./my-registry...
Evaluating 1 Rego policy file(s)...
Registry check passed successfully!
```
*Exit Code*: `0`

### 4.2. Run Check (Failed validation)
Assume we added an attribute `invalid.attribute` without the `ecom.` prefix.
```bash
weaver registry check \
  --registry ./my-registry \
  --policy ./policies
```
**Expected Output (to stderr)**:
```text
Checking registry 'ecom-telemetry-conventions' from path ./my-registry...
Evaluating 1 Rego policy file(s)...
[ERROR] Policy Error: Attribute 'invalid.attribute' must begin with 'ecom.' prefix
Error: Registry check failed with 1 policy errors.
```
*Exit Code*: `1`

### 4.3. Run Generate
```bash
weaver registry generate \
  --registry ./my-registry \
  --templates ./templates/go \
  go ./output/go
```
**Expected Output**:
```text
Resolving semantic convention registry...
Parsing template configurations...
Processing template 'attributes.go.j2' (each)...
- Generated file: ./output/go/attributes_order.go
Processing completed successfully.
```

### 4.4. Run Diff
```bash
weaver registry diff \
  --registry ./my-registry \
  --baseline-registry https://github.com/acme/telemetry-registry.git@main \
  --format markdown
```
**Expected Output**:
```markdown
# Telemetry Schema Diff

## Added Attributes
* `ecom.order.currency` (string)

## Renamed Attributes
* `ecom.order.cost` -> `ecom.order.total_amount`
```
*Note: This is a schema contract diff. It measures contract differences, not runtime process execution drift.*

### 4.5. Run Live-Check
```bash
weaver registry live-check \
  --registry ./my-registry \
  --otlp-grpc-port 4317 \
  --inactivity-timeout 15 \
  --format json
```
**Expected Output (JSON format)**:
```json
{
  "status": "pass",
  "statistics": {
    "total_entities_processed": 142,
    "valid_entities": 142,
    "invalid_entities": 0,
    "processing_time_seconds": 15.04
  },
  "violations": []
}
```
*Note: Live check validates the streaming telemetry feedstock in real-time before it gets written to databases, preventing invalid feedstock from entering the process consequence court.*
