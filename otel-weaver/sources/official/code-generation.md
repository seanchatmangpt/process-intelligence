# Code and Documentation Generation with Weaver

OpenTelemetry Weaver contains a template rendering engine (`weaver_forge`) that transforms resolved semantic convention registries into source code, documentation, or configuration files. This document details the template engine architecture, the structure of the `weaver.yaml` configuration, and template creation.

---

## 1. Code Generation Architecture

Weaver leverages **Jinja2** templates and a **JQ** preprocessor (via `jaq`) to process registry data structures:

```text
Registry (YAML) ────────┐
                        ▼
               [weaver_resolver]
                        │
                        ▼
              Resolved Registry (JSON)
                        │
                        ▼
            [jaq Filter / Preprocessor]
                        │
                        ▼
             Filtered Registry Data
                        │
                        ▼
           [Jinja2 Template Engine] ◄─── Templates & weaver.yaml
                        │
                        ▼
            Generated Code / Docs (Files)
```

---

## 2. Template Configuration via `weaver.yaml`

Every template directory must contain a `weaver.yaml` file to configure whitespace control, custom type mapping, comment formats, JQ filters, and template mappings.

### Example `weaver.yaml` for Go Generation
```yaml
# Whitespace and formatting settings
whitespace_control:
  trim_blocks: true
  lstrip_blocks: true
  keep_trailing_newline: true

# Mapping types from schema to Go
text_maps:
  go_types:
    string: "string"
    int: "int64"
    double: "float64"
    boolean: "bool"
    "string[]": "[]string"

# Acronym configuration to prevent lowercase formatting of standard abbreviations
acronyms:
  - "HTTP"
  - "IP"
  - "TCP"
  - "UUID"
  - "SaaS"

# Formatting specifications for comments in source code
comment_formats:
  go_doc:
    format: text
    prefix: "// "
    trim: true
    enforce_trailing_dots: true

# Global variables accessible in templates
params:
  package_name: "semconv"
  go_version: "1.21"

# The sequence of templates to process
templates:
  - template: "constants.go.j2"
    filter: ".groups[] | select(.type == \"attribute_group\")"
    application_mode: each
    output_path: "attributes/{{ group.id | replace(\".\", \"_\") }}.go"

  - template: "metrics.go.j2"
    filter: "."
    application_mode: single
    output_path: "metrics/instruments.go"
```

---

## 3. Template Execution Modes

Weaver supports two modes of template execution, defined in the `application_mode` field:

### 3.1. `single` Mode
Evaluates the template exactly once. The entire filtered registry is passed to the Jinja2 context. This is ideal for generating unified registries, global constants, or summary documentation.
*   *Jinja context*: The root object represents the registry.
*   *Output*: A single file is written to the specified path.

### 3.2. `each` Mode
Evaluates the template iteratively. Weaver executes the JQ filter, obtains a list of objects, and evaluates the template for each item in the list.
*   *Jinja context*: Each iteration passes a single item (e.g. a group or attribute) under a local variable name (such as `group` or `attribute`).
*   *Output*: Multiple files are generated. The `output_path` can contain Jinja template syntax (e.g. `{{ group.id }}`) to write each file to a unique location.

---

## 4. Preprocessing with JQ (`jaq`)

Before a resolved registry is passed to Jinja2, you can execute a JQ filter to reshape, clean, or reduce the size of the JSON payload. Weaver implements `jaq` in Rust for this purpose.
*   If `filter` is omitted or set to `.`, the full resolved registry is passed unchanged.
*   If `filter` is specified (e.g. `.groups[] | select(.type == "span")`), only the objects that match the filter are passed to the template evaluation stage.

## 5. Writing a Jinja2 Template

Create a Jinja2 template file `templates/go/constants.go.j2` to generate Go attribute constants:

```jinja2
// Code generated by OpenTelemetry Weaver. DO NOT EDIT.
// Upstream schema: {{ schema_url }}

package {{ params.package_name }}

{% if group.brief -%}
// {{ group.brief | comment("go_doc") }}
{%- endif %}
const (
	{%- for attr in group.attributes %}
	{%- if attr.brief %}
	// {{ attr.brief | comment("go_doc") }}
	{%- endif %}
	{{ group.prefix | replace(".", "_") | upper }}_{{ attr.id | replace(".", "_") | upper }} = "{{ group.prefix }}.{{ attr.id }}"
	{%- endfor %}
)
```

### Explanation of Filters:
*   `comment("go_doc")`: Applies the `go_doc` comment format prefix (`// `) and trimming rules declared in `weaver.yaml`.
*   `params.package_name`: Injects the `package_name` parameter defined in `weaver.yaml` or overridden via CLI.

---

## 6. Triggering the Generator

To generate the Go files from a registry located at `./my-registry`:

```bash
weaver registry generate \
  --registry ./my-registry \
  --templates ./templates/go \
  go ./output/go
```
The generator will load `./templates/go/weaver.yaml`, evaluate the templates according to their `application_mode`, compile them, and write the output files into `./output/go`.
