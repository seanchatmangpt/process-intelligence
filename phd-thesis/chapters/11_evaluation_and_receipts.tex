\section{The Evaluation Framework}

The evaluation of this research program is organized around the receipted Chatman Equation: $R \vdash A = \mu(O^{*})$. Each project in the thirty-four-project corpus is evaluated against the following gate criteria:

\begin{enumerate}
  \item \textbf{Receipt existence}: Does a receipt chain exist for the project's claimed consequential actions?
  \item \textbf{Checkpoint verification}: Is there a checkpoint entry in \texttt{checkpoints/} that references verifiable evidence for the claimed verdict?
  \item \textbf{Replay conformance}: Have the project's process events been replayed against the declared process model, producing conformance scores?
  \item \textbf{Gap documentation}: If gate criteria are not all satisfied, is the gap documented in \texttt{gaps/}?
  \item \textbf{Van der Aalst Constitution compliance}: Does the project's evaluation follow the process-mining-first doctrine? Specifically: are the verdicts grounded in event-log evidence, not in code-path inspection or API response analysis?
\end{enumerate}

All five criteria must be satisfied for an \textsc{alive} verdict. Partial satisfaction produces \textsc{partial}. Criterion 1 or 2 failure with no path to resolution produces \textsc{blocked}.

\section{Conformance to the Van der Aalst Constitution}

The Van der Aalst Constitution (documented in \texttt{rules/process-mining-chicago-tdd.md}) establishes the evaluation doctrine: trust event evidence, not code paths or API responses.

The evaluation in this chapter applies the Constitution at every point. Verdicts are not derived from reading source code and concluding that the code, if executed correctly, would produce a conforming process. Verdicts are derived from event logs that have been replayed against declared process models.

This commitment has a direct consequence for the verdict distribution: the preponderance of \textsc{partial} verdicts. A research program that evaluated verdicts by code inspection would find far more \textsc{alive} projects. The code exists. The implementations are substantial. But code is not process evidence. A system that has not produced a replayable event log, checked for conformance, and receipted the result is a system that has not satisfied the Van der Aalst Constitution --- regardless of how mature its implementation appears to be.

The eight \textsc{alive} projects have satisfied the Constitution. The twenty-six \textsc{partial} projects are on a documented path toward satisfying it. The gap registry in \texttt{gaps/} documents each step that remains.

\section{Evidence Receipts Across the Corpus}

The \texttt{receipts/} project (\textsc{alive}) maintains the cross-corpus receipt chain. Each receipt in the chain references:

\begin{itemize}
  \item The project whose action is being certified.
  \item The evidence ($O^{*}$) --- the event log entry or checkpoint reference --- that grounds the certification.
  \item The projection function ($\mu$) applied --- the SPARQL query, conformance algorithm, or governance rule.
  \item The timestamp of evaluation.
  \item The cryptographic commitment linking all components.
\end{itemize}

The receipt chain for the eight \textsc{alive} projects is complete and verified. The partial receipt chains for the twenty-six \textsc{partial} projects document the evidence that exists and identify the gaps precisely. The chain is not a forward-dated promise. It is a backward-dated record. Every entry in the chain corresponds to an event that has occurred, not a plan for future occurrence.
