\subsection{Source Files}
\label{sec:prompts-implementation-sources}

The corpus is organized into two layers of source files.

\textbf{Top-level directives} (16 files in \texttt{prompts/}):
\begin{itemize}
  \item \texttt{downstream\_wasm4pm\_refactor.md} --- Gap-sequenced refactor mandate
    covering GAP\_001 through GAP\_008 with P1/P2/P3 priority tiers and blocking
    claims table.
  \item \texttt{downstream\_wasm4pm-compat\_gap\_close.md} and
    \texttt{DOWNSTREAM\_COMPAT\_GAP\_CLOSE.md} --- Four self-contained compat gap

  \item \texttt{downstream\_ggen\_projection\_integration.md} --- Receipt admission
    pipeline, Ed25519 verification, fitness-to-EBITDA claim taxonomy, and board

  \item \texttt{downstream\_blue\_river\_dam\_lifecycle\_authority.md} --- Six-gate
    lifecycle state machine with proof receipt formats, autonomic authority partition,
    and instance-level case tracking.
  \item \texttt{downstream\_audit\_mesh\_expansion.md} --- Automated capability
    verification and type boundary test requirements.
  \item \texttt{downstream\_m\&a\_deck\_manufacturing.md} --- Slide-to-receipt

  \item \texttt{downstream\_paper\_fixture\_manufacturing.md} --- Academic paper

  \item \texttt{downstream\_pm4py\_benchmark\_comparison.md} --- Throughput and

  \item \texttt{downstream\_public\_standards\_expansion.md} --- XES/OCEL/BPMN

  \item \texttt{v30-execution-mandate.md} --- AGI Court mandate for absolute Blue

  \item \texttt{checkpoint\_\_downstream\_prompts\_complete.md} --- Master

\end{itemize}

\subsection{Commands}
\label{sec:prompts-implementation-commands}

The directives specify no standalone CLI commands for the \texttt{prompts/} corpus
itself. The commands referenced are execution targets in downstream crates:

\begin{itemize}
  \item \texttt{cargo test --test ui\_tests -- --ignored} --- Run compile-fail
    fixtures in \texttt{wasm4pm-compat} to inspect \texttt{.stderr} files for
    E0425/E0432 errors (GAP\_008 diagnostic).
  \item \texttt{npm run test:absence} --- Run the TypeScript absence-proof suite
    before behavioral unit tests in CI.
  \item PM4Py benchmark runner (unspecified invocation) producing wall-clock timing,
    algorithm-specific timing, and peak memory metrics for the seven algorithm
    comparison targets.
\end{itemize}

\subsection{Data and Ontology Surfaces}
\label{sec:prompts-implementation-data}

The corpus references five external data authority surfaces:

\begin{itemize}
  \item \texttt{ma/define\_slide-to-receipt\_map.md} --- The
    \texttt{ProcessIntelligenceVerificationReceipt} JSON schema with UUID, SHA-256
    hashes, Ed25519 signature, and fitness/precision/throughput fields.
  \item \texttt{ma/define\_board\_claim\_taxonomy.md} --- Conformance, efficiency,
    and scalability claim types with board-admissibility rules.
  \item \texttt{ma/define\_operational\_debt\_taxonomy.md} --- Process debt score
    (0--100), structural complexity, rework cycles, and variant explosion metrics.
  \item \texttt{ma/define\_synergy\_claim\_taxonomy.md} --- Behavioral similarity
    index (0--1) and merger complexity tiers (LOW/MEDIUM/HIGH).
  \item \texttt{gaps/GAP\_REGISTER.md} and \texttt{gaps/GAP\_PRIORITY\_MATRIX.md}
    --- The authoritative gap registry and dependency analysis from which all
    engineering task sequences are derived.
\end{itemize}

\subsection{Templates and Rendered Artifacts}
\label{sec:prompts-implementation-templates}

The corpus defines two families of rendered artifact templates:

\textbf{Receipt JSON schemas}: Six gate-specific proof receipts for the Blue River
Dam lifecycle (soundness, behavioral bounds, conformance, repair soundness, discovery
conformance, decommissioning), plus the \texttt{ProcessIntelligenceVerificationReceipt}
schema for ggen claim manufacture, plus the audit trail entry schema for receipt
admission logging.

\textbf{Claim JSON schemas}: Four claim types (conformance, efficiency,
scalability-throughput, operational debt), one synergy claim type, and two risk
mitigation types (non-conformance, signature failure), plus the board summary report
aggregating all claims with aggregate EBITDA impact and auditor signature.

All templates specify that claims at EBITDA impact $> \pm2\%$ must be signed by an
auditor role from the \texttt{RoleKeyRegistry} (\texttt{Auditor}, \texttt{Runner},
\texttt{Board}, \texttt{Validator}) using Ed25519 public key verification.
