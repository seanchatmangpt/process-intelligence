\subsection{Tests}
\label{sec:otel-weaver-exp-005-collector-to-intake-evidence-tests}

The primary test artifact for EXP-005 is \texttt{harness.py}, the synthetic load generator
located at:
\begin{verbatim}
/Users/sac/process-intelligence/otel-weaver/experiments/
  exp-005-collector-to-pi-intake/harness.py
\end{verbatim}

The harness manufactures a three-class feedstock taxonomy:

\begin{itemize}
  \item \textbf{Span A} --- fully compliant span carrying both \texttt{process.pi.instance\_id}
        and \texttt{process.pi.witness.hash}. Expected outcome: admitted by \texttt{filter/pi},
        normalised by \texttt{transform/pi}, written to \texttt{pi\_intake\_events.json}, and
        passing the downstream live-check gate.
  \item \textbf{Span B} --- span missing \texttt{process.pi.instance\_id}. Expected outcome:
        silently dropped by \texttt{filter/pi}; absent from \texttt{pi\_intake\_events.json}.
  \item \textbf{Span C} --- span carrying \texttt{process.pi.instance\_id} but missing
        \texttt{process.pi.witness.hash}. Expected outcome: admitted by \texttt{filter/pi},
        written to \texttt{pi\_intake\_events.json}, but rejected by the downstream
        \texttt{validator.rs} live-check gate in EXP-003, producing a sealed refusal record.
\end{itemize}

These three test classes cover the full admission/rejection surface at the collector boundary.
However, the harness has not been executed against a live collector. The expected outcomes are
specified but unconfirmed by observed collector output. The test surface is PARTIAL: the test
code is manufactured and correct by specification review, but no execution evidence exists.

The \texttt{GGEN\_OTEL\_WEAVER\_PI\_RUNTIME\_001.md} runtime integration checkpoint confirms
that all 62 wasm4pm/wasm4pm-compat/blue\_river\_dam tests pass, but these tests operate on
the downstream processing stack, not on the live collector pipeline. EXP-005 live execution
is not covered by those 62 tests.
