\subsection{Tests}
\label{sec:otel-weaver-exp-004-registry-to-witness-tests}

The primary test surface for EXP-004's runtime behavior is
\texttt{sources/wasm4pm/tests/weaver\_integration\_tests.rs}. This file contains a single
comprehensive test function \texttt{test\_weaver\_integration\_synthesis} that exercises
the full feedstock-to-court pipeline across five cases:

\begin{enumerate}
  \item \textbf{Valid admission.} A nominally correct Schema~V2 feedstock record with all
    required fields present and a valid 64-character BLAKE3 hash is admitted. The test
    asserts that \texttt{admission.payload.instance\_id == "inst-abc-123"}, that
    \texttt{transition\_name} is translated to \texttt{activity\_name} via \texttt{BridgeRx},
    and that the witness fields are preserved unmodified through the \texttt{validate\_and\_project}
    boundary.
  \item \textbf{Missing instance ID.} Feedstock with \texttt{instance\_id: None} is
    refused with \texttt{RefusalCode::MissingInstanceId}. The refusal carries the original
    feedstock and a 64-character BLAKE3 digest of the failure context.
  \item \textbf{Missing activity name.} Feedstock with \texttt{transition\_name: None} is
    refused with \texttt{RefusalCode::MissingActivityName}.
  \item \textbf{Missing witness ID.} Feedstock with \texttt{witness\_id: None} is refused
    with \texttt{RefusalCode::MissingWitnessId}.
  \item \textbf{Invalid witness signature.} Feedstock carrying a \texttt{witness\_hash}
    of fewer than 64 characters (\texttt{"short\_hash"}) is refused with
    \texttt{RefusalCode::InvalidWitnessSignature}.
\end{enumerate}

The runtime checkpoint \texttt{GGEN\_OTEL\_WEAVER\_PI\_RUNTIME\_001.md} records the
following test execution output:
\begin{verbatim}
   Compiling wasm4pm v30.1.2
    Finished test profile [unoptimized + debuginfo] in 0.17s
     Running tests/weaver_integration_tests.rs
running 1 test
test test_weaver_integration_synthesis ... ok
test result: ok. 1 passed; 0 failed
\end{verbatim}
The same checkpoint records 62 total tests passing across the \texttt{wasm4pm},
\texttt{wasm4pm-compat}, and \texttt{blue\_river\_dam} packages with zero side effects.

No unit tests specific to \texttt{codegen/generator.rs} exist. The generator's correctness
is attested only by the existence of the \texttt{generated\_witnesses.rs} output artifact
and its correspondence to the README specification.

\begin{enumerate}
  \item The materialized file \texttt{src/generated\_witnesses.rs} exists on disk and
    matches the README specification --- \textbf{confirmed}.
  \item The integration test \texttt{test\_weaver\_integration\_synthesis} passes and 62

\end{enumerate}

Three success criteria are not fully satisfied:
\begin{enumerate}
  \setcounter{enumi}{2}

    compilation command is insufficient without a crate context --- \textbf{PARTIAL}.
  \item The resolved schema is inlined as a string literal rather than read from a
    Weaver-produced file; genuine Weaver CLI invocation against \texttt{process\_pi.yaml}
    has not been verified --- \textbf{PARTIAL}.
  \item No cryptographic receipt attests the generator execution step --- \textbf{PARTIAL}.
\end{enumerate}

be met --- never declare ALIVE on partial evidence.'' EXP-004 therefore remains PARTIAL.
The parent suite checkpoints (\texttt{GGEN\_OTEL\_WEAVER\_PI\_ALIVE\_001}) carry ALIVE
status for the five-experiment suite as a whole; that ecosystem verdict does not
retroactively close the EXP-004-specific gaps identified above.
