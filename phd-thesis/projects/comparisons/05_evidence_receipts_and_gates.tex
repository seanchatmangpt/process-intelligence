\section{Evidence, Receipts, and Gates}
\label{sec:comparisons-evidence}

\subsection{Tests}
\label{sec:comparisons-evidence-tests}

The comparisons corpus itself contains no executable test infrastructure. All
performance figures are asserted by the source documents rather than measured
by reproducible benchmark scripts in the comparisons directory. This is a known
open gap documented in the corpus (see Section~\ref{sec:comparisons-open-gaps}).

The wasm4pm conformance authority module, which implements the type-law
architecture described by the comparisons corpus, does carry an executable
test suite of eight unit tests in \texttt{conformance\_authority::tests}:
\texttt{test\_admission\_gate\_pass}, \texttt{test\_token\_fitness\_perfect},
\texttt{test\_admission\_gate\_conditional\_with\_override},
\texttt{test\_token\_fitness\_degraded}, \texttt{test\_admission\_gate\_hard\_reject},
\texttt{test\_admission\_gate\_conditional\_without\_override},
\texttt{test\_verdict\_display}, and \texttt{test\_reachability\_heuristic}. All
eight passed on 2026-06-01 as certified in the conformance authority generation
receipt. These tests are evidence that the admission gate and fitness computation
logic behave correctly; they are not in the comparisons directory itself.

\subsection{Checkpoints}
\label{sec:comparisons-evidence-checkpoints}

The comparisons corpus contributes to a single sealed checkpoint:

\textbf{PROCESS\_INTELLIGENCE\_ALIVE\_001} --- sealed 2026-05-31. The ALIVE gate
assessment (\texttt{checkpoints/ALIVE\_GATE\_ASSESSMENT.md}) evaluated 12 criteria.
The comparisons directory satisfied criterion 8: file count target $\geq 4$,
actual 11, verdict MET. All 12 of 12 criteria were met. The threshold for ALIVE
certification is $\geq 10$ of 12, so the verdict is unconditional.

The checkpoint authorizes: board-level claim delivery for any claim traceable to
a receipt in the registry; M\&A diligence package assembly; wasm4pm graduation
initiation; PAPERLAW\_ALIVE workflows; and standards-based conformance claims for
XES, OCEL 2.0, BPMN 2.0, and Petri net soundness.

The checkpoint explicitly prohibits: claims based on unadmitted (raw) event logs;
conformance scores without a named witness; M\&A claims without corresponding
receipts in the registry; and wasm4pm integration without \texttt{Admission<T, W>}
typing at the API boundary.
