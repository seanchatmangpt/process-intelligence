\subsection{Purpose}
\label{sec:research-open-ontologies-purpose}

The \texttt{research-open-ontologies} project is the federated ontology authority layer for the
Process Intelligence research program. Its purpose is to provide a single, validated, acyclic
RDF corpus that grounds all process intelligence claims in public vocabularies: PROV-O
(\texttt{http://www.w3.org/ns/prov\#}), SKOS (\texttt{http://www.w3.org/2004/02/skos/core\#}),
DCTERMS (\texttt{http://purl.org/dc/terms/}), SHACL (\texttt{http://www.w3.org/ns/shacl\#}),
DCAT (\texttt{http://www.w3.org/ns/dcat\#}), and OWL
(\texttt{http://www.w3.org/2002/07/owl\#}).

Without a validated, dependency-consistent ontology corpus, M\&A claims cannot be board-admissible,
conformance verdicts cannot carry named witnesses, and the ggen manufacturing pipeline cannot emit
BLAKE3-receipted artifacts. The open-ontologies surface is therefore a prerequisite gate, not a
secondary concern. The COVENANT governing this program states: ``Whoever controls admissible
process truth controls downstream data, audit, governance, automation, intelligence.'' The
open-ontologies project is the enforcement point for that covenant at the RDF layer.

\subsection{Primary Research Role}
\label{sec:research-open-ontologies-role}

The thesis role of this project is \textbf{open-ontology-research-and-rdf-authority}. In the
full-lifecycle process intelligence architecture, this project occupies the governance layer
between raw evidence (OTel traces, event logs) and board-admissible claims (M\&A projections,
conformance verdicts). Every class, property, and named individual defined in the corpus
either derives from a public open standard or is explicitly declared as a local extension
with a \texttt{process-intelligence.local} or \texttt{https://process.intelligence/} base URI.

The project does not manufacture artifacts directly. Instead, it certifies that the ontology
graph is in a valid state, enabling downstream ggen SPARQL-to-Tera rules to manufacture Rust
witness-marker enums, Markdown process-form documentation, and WIT boundary definitions from
a trustworthy knowledge base.
