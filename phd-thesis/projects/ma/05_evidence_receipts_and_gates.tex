\section{Evidence, Receipts, and Gates}
\label{sec:ma-evidence}

\subsection{Tests}
\label{sec:ma-evidence-tests}

The \texttt{ma/} module contains no programmatic test harness. There are no unit tests, no
integration tests, and no executable proof-gate scripts within the module itself. This is not
an oversight---the module is a doctrinal and specification layer whose ``tests'' are the
proof gates embedded in the claim taxonomy definitions and the admissibility protocol.

The practical proof gates are:

\begin{itemize}
  \item \textbf{Receipt completeness check:} Every slide in the board deck must have a
    corresponding receipt UUID in the Slide-to-Receipt Map. An orphaned assertion (slide
    without receipt) is a gate failure.
  \item \textbf{Admissibility threshold check:} All receipts must report fitness $f \ge 0.95$,
    precision $p \ge 0.90$, generalization $g \ge 0.85$, simplicity $s \ge 0.80$.
  \item \textbf{Soundness certificate check:} All submitted process models must carry a
    WF-net soundness certificate. An unsound model is a gate failure regardless of reported
    fitness.
  \item \textbf{Replication tolerance check:} An independent auditor replay of any receipt's
    wasm4pm query must produce fitness and precision values within $\Delta f, \Delta p <
    10^{-6}$ of the original. Deviation beyond this tolerance is a gate failure.
  \item \textbf{Behavioral similarity check:} All synergy claims must report
    $\text{Sim}(M_1, M_2, C) \ge 0.75$ (Weidlich 2011). Claims below this threshold are
    admissible only at T2 (Coverage), not at T3 (Conformance) or above.
\end{itemize}

Negative testing---injection of non-conforming traces to verify that \texttt{wasm4pm} queries
correctly refuse them---is specified in the admissibility framework but has not been executed
against real enterprise event logs as of the thesis writing date (2026-06-01). This is an open
gap (see Chapter~7).
