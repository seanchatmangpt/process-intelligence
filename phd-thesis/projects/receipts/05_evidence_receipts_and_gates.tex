\subsection{Tests}
\label{sec:receipts-evidence-tests}

The receipts corpus is underwritten by two independent Rust unit test suites. The
conformance authority module (version \texttt{v30.1.2}, 664 lines of Rust) carries
seven unit tests, all passing. The tests and their functional scope are enumerated
below.

\begin{description}
  \item[\texttt{test\_admission\_gate\_pass}] Verifies that a \texttt{ConformanceVerdicts}
    struct with fitness $\geq 0.95$ and precision $\geq 0.90$ passes the
    \texttt{ConformanceAdmissionGate} and is marked board-admissible.
  \item[\texttt{test\_token\_fitness\_perfect}] Verifies the token-based replay formula
    $f = 1 - (\sum m / \sum c) - (\sum r / \sum p)$ returns $1.0$ when missing and
    remaining token counts are zero.
  \item[\texttt{test\_admission\_gate\_conditional\_with\_override}] Verifies that a result
    with fitness between $0.90$ and $0.95$ can be conditionally admitted under an explicit
    override authority, with the override recorded in the receipt.
  \item[\texttt{test\_token\_fitness\_degraded}] Verifies that non-zero missing and remaining
    token counts produce a fitness value strictly below $1.0$ according to the van der Aalst
    formula.
  \item[\texttt{test\_admission\_gate\_hard\_reject}] Verifies that a fitness value below
    $0.90$ causes the gate to emit a hard-reject verdict and refuse to forward the receipt
    for signing. This test is the programmatic enforcement of the board admissibility floor.
  \item[\texttt{test\_verdict\_display}] Verifies the string representation of
    \texttt{ConformanceVerdicts} for human-readable receipt output.
  \item[\texttt{test\_reachability\_heuristic}] Verifies that the reachability heuristic
    used in A* alignment (Adriansyah 2014) correctly estimates the cost of aligning a
    partial trace against a reference model.
\end{description}

The Blue River Dam orchestrator carries five additional unit tests, all passing:
\texttt{test\_governance\_hierarchy} (MAPE-K role authority chain),
\texttt{test\_lifecycle\_state\_machine} (lawful state transitions),
\texttt{test\_quality\_gate\_soundness} (gate rejection logic),
\texttt{test\_conformance\_metric} (end-to-end metric pipeline), and
\texttt{test\_mape\_k\_knowledge\_persistence} (knowledge base durability across cycles).
