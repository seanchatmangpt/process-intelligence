# Downstream Directive: M&A Deck Manufacturing

This document outlines the rules and verification steps for manufacturing investment-grade, board-ready M&A slide decks. All generated slide assertions must be directly mapped to underlying process mining artifacts.

## 1. M&A Slide-to-Receipt Mapping
Every slide deck generated by downstream tools must have a corresponding validation map linking slide claims to cryptographic process receipts.
- **Financial EBITDA Diligence**: Slide claims regarding cost savings or EBITDA adjustments due to process standardization must map to:
  1. The path cost models calculated during token replay.
  2. The raw event log hash ($H_{log}$) that generated the deviation metrics.
- **Operational Risk Slide Mapping**: Slide claims showing process debt, compliance rates, or control-flow vulnerabilities (e.g., Segregation of Duties violations) must link directly to:
  1. The Petri net model hash ($H_{model}$).
  2. The exact alignment path that matches the violation trace.

## 2. Process Debt and Risk Calculations
Downstream generation tools must calculate the following metrics:
- **Synergy Projection Value**:
  $$V_{\text{synergy}} = \sum_{i \in \text{parallelizable}} \text{latency}_i \times \text{frequency}_i \times (1 - \text{dependency\_coeff}_i)$$
- **Process Debt Value**:
  $$V_{\text{debt}} = \sum_{j \in \text{non\_conforming}} \text{rework\_cost}_j \times \text{recurrence}_j \times (1 - \text{insurance\_coverage}_j)$$
- **Control-Flow Compliance**:
  $$\operatorname{Compliance} = \frac{|L_{\text{conforming}}|}{|L_{\text{total}}|}$$

All calculations must be executed via the `wasm4pm` engine and have the resulting fitness/conformance numbers embedded in the slide XML metadata.

## 3. Defensibility and Auditing
- **Verification Portal**: Decks must contain a references index allowing a potential buyer's technical team to run a command (e.g., `ggen verify --manifest <manifest-file>`) to download the log and verify the exact calculations for every slide claim.
- **Laundering Refusal**: Expose any assertions that are unsupported by the event log, raising a validation failure during deck compilation if an unverified operational claim is inserted.
