This contract defines the exact redaction rules and publication checklist that govern

## Redaction Rules

### Rule R-01: No Broker or Exchange Names

**Scope:** All dissertation chapters, appendices, figures, captions, acknowledgments,
supplemental material, and presentation slides.

**Prohibited:** Any named broker, exchange, dark pool, ECN, or execution venue.
Examples of prohibited terms: [venue names omitted intentionally].

**Permitted:** "a synthetic market stream", "a distributed multi-venue observation model",
"a representative market data fixture".

**Enforcement:** Full-text search before submission. Any match is a blocker.

---

### Rule R-02: No Wallet Addresses or Private Keys

**Scope:** All text, code listings, appendices, footnotes, and supplemental data.

**Prohibited:** Any cryptographic key material, wallet address, account identifier, or
API credential string.

**Permitted:** Key derivation concepts described at the algorithm level without instantiation.

**Enforcement:** Automated scan for hex strings of length >= 32. Any match is a blocker.

---

### Rule R-03: No Internal Crate Names Beyond Public Abstraction

**Scope:** All code listings, architecture diagrams, and technical appendices.

**Prohibited:** Internal Rust crate names, module paths, or file paths that reveal
internal project structure not publicly disclosed.

**Permitted:** "CONSTRUCT8", "GraphPlayer", "LogicPlayer", "VectorClock8" (public
abstraction names). Rust test function names from the public witness set.

**Enforcement:** Code listing review. Any crate path referencing internal adapters
or capital-flow systems is a blocker.

---

### Rule R-04: No "Deploy This for Capital Gain" Language

**Scope:** All text. No exceptions.

**Prohibited:** Any sentence implying that the described system produces trading profits,
outperforms benchmarks on live data, or should be deployed for financial return.

**Examples of prohibited language:**
- "This approach yields positive returns in live markets."
- "CONSTRUCT8 outperforms a random baseline in production."
- "Deploying the graph-state machine generates alpha."

**Permitted:** "The synthetic fixture demonstrates state-count divergence."
"Representational separability is the result, not prediction superiority."

**Enforcement:** Human review of all claims sections. Any instance is a blocker.

---

### Rule R-05: Synthetic Data Labeled as Synthetic Everywhere

**Scope:** All figures, tables, code outputs, and appendices containing market-like data.

**Required label:** Every figure or table caption must include "(synthetic data)" or
"Source: synthetic fixture" if the data was generated by a test fixture rather than
observed in a real market.

**Prohibited:** Presenting synthetic fixture outputs without labeling, in any context
where the reader might infer live market validation.

**Enforcement:** Caption audit before submission. Missing label is a blocker.

---

### Rule R-06: Defense Sentence Uses "Representational Separability" Not "Profit Advantage"

**Scope:** Abstract, introduction, conclusion, and any summary of the dissertation's
contribution.

**Required language:** The contribution must be framed as "representational separability"
— the mathematical property that the same stream yields different reachable state spaces.

**Prohibited framing:** "profit advantage", "trading edge", "alpha generation", "market
outperformance", "return enhancement".

**Enforcement:** Abstract and conclusion review. Any prohibited framing is a blocker.

---

### Rule R-07: No Actuation Path Description

**Scope:** All text, architecture diagrams, pseudocode, and appendices.

**Prohibited:** Any description of how coordinate-system alpha transitions from theorem
to execution authority. No adapter mechanics, no consequence cell firing order, no
production integration sequence.

**Permitted:** "CONSTRUCT8 provides a branchless graph-state mutation mechanism" (stops
here). No downstream description.

**Enforcement:** Architecture diagram review. Any diagram showing connection from
CONSTRUCT8 to capital allocation or execution systems is a blocker.

---

### Rule R-08: No Market Instrument Thresholds

**Scope:** All code listings, parameter tables, configuration examples.

**Prohibited:** Specific numerical thresholds used in production EventHorizonTelescope
detection, VectorClock8 lane assignments, RelationBreak price gap values, or volume
horizon collapse percentages from production calibration.

**Permitted:** Example threshold values clearly labeled as illustrative (e.g.,
"threshold = 10 (illustrative, not production-calibrated)").

**Enforcement:** Parameter table review. Any value that matches production calibration
without illustrative label is a blocker.
